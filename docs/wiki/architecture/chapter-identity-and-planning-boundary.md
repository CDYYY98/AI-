# 章节身份与卷规划边界

## Background

卷规划里的章节和章节执行区里的章节不是同一种身份。卷规划章节承载拆章意图、任务单、场景卡和节奏位置；执行章节承载正文、生成状态、审校结果、质量修复和状态回灌。过去如果只按标题或序号匹配，两章重名、章节移动、旧标题保留或用户手动调整后，规划同步可能把任务单写到错误的执行章节上。

## Decision

`VolumeChapterPlan.id` 是卷规划章节身份，`Chapter.id` 是执行章节身份。两者之间必须通过 `VolumeChapterPlan.chapterId` 建立显式链接。同步卷规划到章节执行区时，显式链接优先级高于序号和标题。

## Current Rule

- 如果 `VolumeChapterPlan.chapterId` 指向存在的执行章节，同步必须使用该执行章节，不能再用同序号或同标题章节覆盖判断。
- 如果 `VolumeChapterPlan.chapterId` 为空，才允许按章节序号、标题等旧规则兜底匹配，并在匹配成功后把执行章节 id 写回规划章节。
- 如果 `VolumeChapterPlan.chapterId` 指向的执行章节不存在，不得强行匹配同序号或同标题章节；这类规划章节应按未链接章节处理，避免把规划误挂到错误正文。
- 新建执行章节后，必须把新 `Chapter.id` 回写到卷工作区行和版本 JSON，保证后续同步沿用同一执行章节。

## Affected Scope

这个规则影响卷规划、节奏拆章、章节执行同步、自动导演批量推进和任何读取卷工作区版本 JSON 的恢复链路。后续如果新增章节重排、章节合并、拆分或导入功能，也应先维护规划身份与执行身份的链接，再处理标题、序号或正文资产。

## Failure Modes

- 仅按标题匹配：重复标题会把任务单、场景卡或字数目标写入错误章节。
- 仅按序号匹配：章节移动后，旧正文可能被新规划覆盖。
- 新建章节不回写链接：下一次同步可能再次创建章节，或把同一个规划章节误判为未同步。
- 失效链接继续兜底猜测：被删除或迁移的执行章节可能导致规划挂到无关正文，后续审校和修复都会沿着错误章节继续。
