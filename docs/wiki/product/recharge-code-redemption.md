# 卡密兑换与灵感值到账

## 背景

产品早期收费更适合先用小额卡密验证付费意愿，而不是一开始接入完整支付回调。卡密让用户在购买或领取后自行兑换灵感值，管理员不需要实时在线人工加额度，也能保留兑换记录和卡密状态。

## 当前规则

- 卡密等同于可兑换余额，完整卡密只在后台生成后显示一次；后续列表只展示前缀和尾号。
- 用户只能在个人中心兑换卡密。兑换成功后，本地账户额度和 NewAPI 用户额度必须同步增加。
- 卡密状态至少区分 `unused`、`redeeming`、`redeemed`、`disabled`。未使用卡密可以停用，已兑换卡密不能重复使用。
- 兑换成功后账户升级为创作账户，方便后续模型路由按账户类型选择模型。
- 后台生成卡密时必须记录面额、批次、备注、创建管理员；兑换时记录兑换用户和兑换时间。

## 失败处理

- 如果卡密不存在、已兑换或已停用，用户应看到明确原因，不能模糊提示系统错误。
- 兑换过程中先把卡密标记为处理中，再同步 NewAPI 额度。同步失败时应把卡密恢复成未使用，避免用户失去卡密但没有到账。
- 如果卡密卡在处理中，管理员应优先检查 NewAPI 同步和服务日志，再决定是否人工处理，不要直接补发新卡密掩盖账务状态。
